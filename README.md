# OpenAlbert

Персональный Telegram-бот на Go с долговременной памятью, фоновыми задачами,
браузерными инструментами, распознаванием голосовых сообщений и собственным
Ubuntu-компьютером с доступом по SSH и `sudo` без пароля.
LLM подключается через внешний OpenAI-совместимый API.

Нативный [клиент macOS и API](docs/desktop.md) продолжают тот же личный разговор,
показывают поручения, память и файлы. Исходники клиента: `apps/macos`.

- [Локальная разработка и тесты](docs/development.md): `deploy/compose.local.yaml` собирает код из checkout.
- [Запуск готовых образов и публикация](docs/deployment.md): `deploy/compose.yaml` получает образы из GHCR.
- [Архитектура и документация](docs/README.md).

Проверки, тесты и сборки выполняются локально: `task check`, `task test`,
`task images` и полный прогон `task verify`. Логи и отчёты сохраняются в
`reports/local/`; `task reports` показывает последний результат.
[Команды и настройка](docs/local-checks.md). Публикация Linux AMD64/ARM64 образов
запускается отдельно через `task publish`. Фактическая скорость распознавания
речи на Raspberry Pi 5 с 64-битной ОС ещё требует замеров.

Рабочие `.env`, ключи, история, вложения и память находятся вне Git и образов.

## Структура репозитория

```text
apps/
  backend/          Основное Go-приложение: агент, API, инспектор, память и задачи
  macos/            Нативный клиент macOS
services/
  computer/         Ubuntu-среда исполнения команд
  stt/              Сервис распознавания речи
  log-gateway/      Приём и доставка Docker-логов
  postgres/         Инициализация PostgreSQL
  temporal/         Конфигурация Temporal и описание Temporal UI
  minio/            Сборка MinIO и инициализация бакета
  victorialogs/     Настройки и описание хранилища логов
deploy/             Совместное развёртывание: Compose, Bake и сетевые шаблоны
tools/              Общие проверки, smoke-тесты и публикация
docs/               Документация, схемы и сайт документации
```

В папке компонента находятся его исходники, тесты, ресурсы и Dockerfile либо
конфигурация стороннего сервиса. `deploy/` связывает компоненты в систему.
Go-приложение и Go-сервисы используют единые `go.mod` и `go.sum` в корне;
пакеты `internal` каждого компонента доступны только внутри его каталога.

Команды Task выполняются из корня. Для ручного запуска локального стека:

```sh
docker compose --project-directory . -f deploy/compose.local.yaml up -d --build
```

`--project-directory .` сохраняет `.env`, контекст сборки и постоянные данные
`container_data/` в корне checkout. Для установки без исходников скачай
`deploy/compose.yaml` как `compose.yaml` в каталог установки — подробности в
[руководстве публикации и установки](docs/deployment.md#установка-без-исходников).
