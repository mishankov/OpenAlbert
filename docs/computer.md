# Компьютер пользователя

[К содержанию](README.md)

Компьютер — самостоятельное окружение пользователя, доступное Альберту по SSH.
Основной Compose не создаёт и не запускает компьютер. Его образ не собирается
и не публикуется вместе с релизами. Пустой `COMPUTER_SSH_ADDRESS` отключает
инструменты компьютера; остальные возможности Альберта продолжают работать.

Можно подключить существующую Linux-машину или явно создать отдельный контейнер
на своём Docker-хосте. ОС, программы и резервные копии обслуживает пользователь;
Альберт автоматически устанавливает и обновляет только свой исполнитель.

## Существующая машина

Нужна Linux-машина с SSH-сервером, Python 3.9+ и `/bin/bash`. SSH-пользователю
нужна запись в домашний каталог; отдельный пользователь `albert`, `/workspace`
и `sudo` не обязательны. Разреши вход по паролю или публичному ключу.

В `.env` Альберта задай:

```dotenv
COMPUTER_SSH_ADDRESS=your-machine.example:22
COMPUTER_SSH_USER=your-user
COMPUTER_SSH_PASSWORD='your-password'
```

Укажи ровно один способ входа. Для входа по ключу оставь `COMPUTER_SSH_PASSWORD=`
и задай `COMPUTER_SSH_KEY_FILE=/data/computer/id_ed25519`. В основном Compose
положи приватный ключ в `container_data/computer/client/id_ed25519`: каталог
монтируется в backend как `/data/computer` только для чтения. Приложение работает
от UID 10001: ключ должен быть доступен этому UID и иметь права 0600.
При запуске backend без Docker путь относится к файловой системе его процесса.
Зашифрованные ключи с отдельной парольной фразой пока не поддерживаются.

Адрес должен быть доступен из контейнера приложения. Проверка ключа SSH-сервера
отключена: `known_hosts` и `COMPUTER_SSH_KNOWN_HOSTS_FILE` больше не используются.
Соединение шифруется, но подлинность компьютера не проверяется.

## Автоматическая подготовка и обновление

Первый вызов любого инструмента компьютера устанавливает исполнитель по SSH.
Отдельной утилиты или команды настройки нет. Перед каждым запросом backend:

1. Проверяет Linux, Python 3.9+, Bash и доступность каталогов в `~/.openalbert`.
2. Сравнивает SHA-256 установленного исполнителя с кодом, встроенным в backend.
3. Если нужной версии нет или файл повреждён, передаёт код по SSH и атомарно
   сохраняет `~/.openalbert/runners/<sha256>.py`. Неизменившийся код не передаётся.
4. Только после успешной подготовки передаёт пользовательскую операцию исполнителю.

Системные пакеты автоматически не устанавливаются. При отсутствии зависимостей
или ошибке подготовки инструмент сообщает причину и не передаёт команду на запуск.
Установка и обновление не требуют `sudo`.

Рабочий каталог по умолчанию — `~/.openalbert/workspace` на удалённой машине.
Абсолютный `cwd` можно указать явно; узнать фактический путь помогает `pwd`.
Записи операций остаются в `~/.openalbert/executions`, включая записи прежнего
исполнителя. Идентификаторы, результаты и защита от повторного выполнения сохраняются.

Изменение кода исполнителя попадает в backend при его сборке. При следующем
SSH-подключении новая версия устанавливается автоматически. Старые версии
сохраняются: активные и ожидающие команды используют свой файл кода, а новые
операции — версию подключившегося backend. Все версии используют общую блокировку
команд и общий каталог операций. Обновление не останавливает процессы и не удаляет
рабочие файлы. Сам backend не запускает компьютер и не обновляет его ОС.

## Создание отдельного локального компьютера

`services/computer/` — необязательный шаблон для пользовательской сборки Ubuntu
24.04 с SSH, Python, Git и пользователем `albert` с `sudo` без пароля. Шаблон
не входит в основной Compose или каталог релизных сборок. Скопируй его **за пределы
checkout и каталога установки Альберта**, чтобы обновления исходников не меняли
конфигурацию компьютера. Для установки без checkout можно отдельно скачать эти
файлы из выбранного коммита.

```sh
# Из checkout; путь назначения ещё не должен существовать:
cp -R services/computer "$HOME/albert-computer"
cd "$HOME/albert-computer"
# Только при первом создании нового окружения:
docker compose build computer
docker compose up -d --no-build --wait
```

Образ создаётся локально как `openalbert-computer:local`; загрузки из реестра
отключены. Компьютер живёт в собственном проекте `openalbert-computer` и сети
с таким же именем. Одноразовый `computer-init` создаёт ключи клиента и сервера,
при повторном запуске сохраняет SSH-идентичность. Клиентский приватный ключ
доступен только приложению; на компьютере находится лишь его публичный ключ.
SSH-порт не публикуется на хосте. Компьютер имеет исходящий интернет, Docker socket
и секреты приложения в него не монтируются.

Для подключения добавь в `.env` **Альберта** абсолютный путь к этому каталогу
и подключи сохранённый там адаптер Compose:

```dotenv
COMPUTER_DIRECTORY=/absolute/path/to/albert-computer
COMPUTER_SSH_ADDRESS=computer:22
COMPUTER_SSH_USER=albert
COMPUTER_SSH_KEY_FILE=/data/computer/id_ed25519
COMPOSE_FILE=compose.yaml:/absolute/path/to/albert-computer/app.compose.yaml
```

Для запуска из checkout вместо `compose.yaml` укажи `deploy/compose.local.yaml`
и по-прежнему используй `--project-directory .`. Если уже используешь другие
Compose overrides, сохрани их в `COMPOSE_FILE`. Явный `-f` переопределяет этот список:
тогда передавай также `-f /absolute/path/to/albert-computer/app.compose.yaml`.
Адаптер подключает только приложение к внешней сети и монтирует клиентские ключи
только для чтения; сервисов компьютера в проект Альберта он не добавляет.

Обновляй Альберта обычными `docker compose pull` и `docker compose up -d` из его
каталога установки. Эти команды, включая пересоздание приложения и
`down --remove-orphans`, не пересоздают отдельный компьютер. При следующем обращении
backend обновит только свой исполнитель, если его код изменился. Чтобы отключить tools,
оставь `COMPUTER_SSH_ADDRESS=`; чтобы убрать подключение к сети, убери адаптер
из `COMPOSE_FILE` и пересоздай приложение.

Операции самого компьютера выполняются отдельно, из `$HOME/albert-computer`:

```sh
docker compose exec --user albert computer bash
docker compose stop computer
docker compose start computer
```

Не выполняй для настроенного компьютера `build`, `up --build`, `--force-recreate`
или `down` без снимка системного диска. Домашний каталог и `/workspace` находятся
в bind mounts, но установленные через `apt` пакеты, `/usr/local`, `/etc` и прочие
изменения системы живут в записываемом слое контейнера. Его пересоздание потеряет
эти изменения. Для обновления ОС используй отдельную процедуру с резервной копией.
Пределы CPU/памяти задаются `COMPUTER_CPUS=2` и `COMPUTER_MEMORY_LIMIT=2g` в `.env`
компьютера; изменение конфигурации тоже может потребовать пересоздания.

## Перенос прежнего встроенного компьютера

До первого обновления на эту схему сохрани существующий контейнер. Одного
копирования `container_data/computer` недостаточно для пакетов и системных файлов.
Команды ниже относятся к установке готовых образов; для checkout используй её
прежний Compose с `--project-directory . -f deploy/compose.local.yaml`.

1. Сохрани старый Compose, `.env` и резервную копию данных. Из старой установки
   останови приложение и компьютер и создай локальный снимок его системного слоя:

   ```sh
   docker compose stop openalbert computer
   old_computer=$(docker compose ps -a -q computer)
   test -n "$old_computer"
   docker commit "$old_computer" openalbert-computer:local
   ```

2. Скопируй шаблон в новый отдельный каталог, как описано выше. **Не собирай образ**:
   вместо него используется снимок прежнего компьютера. Перенеси копии каталогов
   `client`, `server`, `home`, `workspace` из прежнего `container_data/computer`
   в новый каталог, сохранив владельцев и права. Например, на Linux:

   ```sh
   sudo cp -a /path/to/installation/container_data/computer/. /path/to/albert-computer/
   cd /path/to/albert-computer
   docker compose up -d --no-build --wait
   ```

3. Проверь установленные пакеты, SSH-идентичность и рабочие файлы через
   `docker compose exec --user albert computer bash`. Добавь адаптер и настройки
   в `.env` Альберта, затем замени основной Compose и обнови приложение.
   Проверь выполнение команды через Альберта. Старый остановленный контейнер
   и исходные данные сохраняй до успешной проверки. Только после неё можно удалить
   старые orphan-контейнеры основного проекта.

Снимок `docker commit` не содержит bind mounts: для переноса нужны и образ,
и все четыре каталога с данными.

## Резервирование и проверки

Отдельный компьютер резервируется пользователем отдельно от Альберта. Автоматический
бэкап приложения не останавливает его и не архивирует внешние ключи или диск.
Для согласованной копии останови компьютер, сохрани его образ после `docker commit`
через `docker image save`, а также весь отдельный каталог с владельцами и правами.
После копирования запусти компьютер через `docker compose start computer`.
Образ и каталог содержат личные данные и ключи; храни копию в защищённом месте.
Восстановление требует `docker image load`, восстановления каталога и запуска
с `--no-build` с тем же тегом `COMPUTER_IMAGE`.

```sh
# Из checkout: одноразовая сборка и проверки без реальных Telegram/LLM:
task test:computer
```

Проверка создаёт изолированные контейнеры и синтетические данные. Она проверяет
вход по ключу и паролю, автоматическую установку без sudo, обновление при активной
команде, файлы, отмену и повторы команд, а также сохранение ID компьютера,
системных изменений и `/workspace` при пересоздании и удалении проекта приложения.
После проверки одноразовые контейнеры, данные, сети и образ удаляются.
Контракт инструментов — в [разделе удалённого компьютера](tools.md#удалённый-компьютер).
