# macOS: разработка и проверки в отдельной VM

Локальные проверки AppKit, клавиатуры и снимки интерфейса выполняются в отдельной
macOS VM. Окна и фокус остаются в гостевой системе. Компиляция приложения и XCTest
происходит на хосте; внутри VM запускаются только готовые исполняемые файлы.
При недоступной VM команда завершается с ошибкой, без запуска на рабочем столе
пользователя.

## Подготовка

Нужны Apple silicon, полный Xcode 27, Python 3.9+ и Tart с Guest Agent в образе.
Версия Xcode и версия macOS SDK гостя должны совпадать с хостом; macOS гостя —
не ниже версии SDK и не ниже 27. `doctor` показывает фактические версии.
Установить Tart можно через `brew install openai/tools/tart`. Runner также
находит приложение Tart в
`~/Library/Application Support/polka-development/tart/tart.app`; используется
только исполняемый файл, без VM, профилей и ключей Полки.

```sh
python3 apps/macos/desktop_vm.py setup
python3 apps/macos/desktop_vm.py doctor
```

`setup` использует уже закешированный OCI-образ
`ghcr.io/cirruslabs/macos-golden-gate-xcode:27`. Если в кеше есть его единственный
immutable digest, клонируется именно этот digest. Отдельная VM называется
`albert-desktop-development`; ей выделяются 4 CPU, 12 ГБ RAM и экран 1920×1080.
Сам `setup` не запускает VM. При отсутствии образа нужно сначала явно загрузить
его через `tart pull`; runner не начинает большую загрузку самостоятельно и не
клонирует существующую VM Полки. Автоматическое удаление Tart-кеша отключено.

Существующая VM без корректной метки владельца не принимается. Метка содержит
имя, образ, UID и идентичность каталога VM. Runner не перезаписывает VM, не
перехватывает уже работающий сеанс и не останавливает VM по одному имени.

## Обычные команды

```sh
# Все собранные Core- и UI-тесты внутри гостя
python3 apps/macos/desktop_vm.py test

# Настоящее окно, редактор и клавиатурный smoke
python3 apps/macos/desktop_vm.py smoke

# Снимки интерфейса с синтетическими сообщениями, поручениями и голосовым черновиком
python3 apps/macos/desktop_vm.py screenshots

# Открыть текущую сборку для разработки в видимом окне VM
python3 apps/macos/desktop_vm.py run
```

`test` и `screenshots` вызывают `swift build --build-tests` на хосте, переносят
обе сборки `AlbertCoreTests.xctest` и `AlbertUITests.xctest`, исправляют пути
загрузки framework и подписывают локальные копии ad-hoc. Затем гостевой
`xcrun xctest` запускает тесты без SwiftPM, swiftc или asset compiler. Успех
Core-тестов без выполнения клавиатурного `InterfaceTests` не считается успехом
UI-проверки. Отдельный optional Go ↔ Swift HTTP-тест остаётся самостоятельной
проверкой; production API, Telegram и модель этим runner не вызываются.

`task test:macos` объединяет tooling, Go/Swift-контракт, гостевые XCTest и smoke
release-сборки с общим [отчётом прогона](local-checks.md).

Обычные проверки работают без окна Tart. Только явная команда `run` открывает
видимую VM. Приложение запускается с отдельным гостевым профилем: при желании
подключение настраивается внутри гостя, ключи и история хоста туда не переносятся.
Закрытие приложения завершает сеанс. Ctrl-C, SIGTERM, ошибка и таймаут завершают
принадлежащие вызову процессы и останавливают его VM. По умолчанию лимит проверки
— 15 минут, видимого сеанса — 8 часов; его можно изменить через `--timeout`.
SIGKILL и выключение хоста не дают процессу выполнить cleanup; следующий вызов
откажется захватывать оставленную работающей VM.

Параметры:

- `--configuration debug|release` — конфигурация компиляции, по умолчанию debug.
- `--timeout 900` — лимит гостевой операции в секундах.
- `--lock-timeout 600` — ожидание общей блокировки между worktrees.
- `--output /absolute/directory` — родитель для нового каталога диагностики.
- `--app /absolute/Albert.app` — только для `smoke`: проверить уже собранный bundle
  без пересборки и смены подписи; используется при локальном выпуске релиза.
- `--assets /absolute/directory` — только для `screenshots`; используются ровно
  `lake.jpg` и `forest.jpg`. По умолчанию это `apps/macos/Fixtures`.

`ALBERT_TART` задаёт абсолютный путь к Tart.
`ALBERT_VM_NAME=albert-<имя>` и `ALBERT_VM_IMAGE` позволяют выбрать отдельную VM и
другой уже закешированный OCI-образ. Изменение образа существующей управляемой VM
не допускается: используйте новое имя. `ALBERT_VM_STATE` меняет каталог меток,
но не путь общей блокировки.

## Граница изоляции

Гостю доступны два отдельных share: read-only входы и новый writable каталог
результатов. Во входы входят только готовые bundle, helper экрана, копии
`Package.swift`, `Package.resolved`, `version.json` и Swift-файлов `Sources` /
`Tests`. Это текущие файлы worktree, включая новые и отредактированные, без
сканирования всего Git-репозитория. Для явной команды снимков добавляются только
два разрешённых JPEG. Исходные symlink не обходятся; symlink внутри bundle должны
быть относительными и оставаться внутри подготовленных входов. Готовые исполняемые
файлы и framework передаются в tar-архиве и распаковываются на диск гостя: это
сохраняет символические ссылки Sparkle, которые некорректно читаются через virtiofs.

`.env`, `.git`, build databases, пользовательские профили, SSH agent, сертификаты,
закрытые ключи и переменные окружения с токенами не передаются. Локальная сборка
не получает release signing/updater credentials. Аудио, USB и общий clipboard
Tart отключены для всех режимов, включая видимый `run`. Тесты голоса используют
подменяемый драйвер и синтетический AAC; доступ к микрофону хоста не нужен.

Перед запуском проверяются гипервизор, console UID, GUI-сессия и версии Xcode /
SDK. Настройка экрана и скрытие системных overlay выполняются только внутри
проверенного гостя. Readiness-пробы ограничены по времени и повторяются до трёх
минут; зависший Guest Agent не оставляет запущенные transport-процессы.
Общая `flock`-блокировка находится вне checkout и сериализует все worktrees и
имена VM Альберта. При завершении сохраняется inode lock-файла, чтобы ожидающие
процессы не смогли обойти блокировку.

## Результаты

Каждый запуск создаёт `apps/macos/build/vm/<UUID>/`. Там находятся `result.json`,
`inputs.json` с SHA-256 подготовленных файлов, логи компиляции, загрузки,
readiness и гостевых тестов; у снимков — каталог `guest/screenshots/`. Writable share ограничен каталогом
`guest/`; host-логи и аттестация находятся вне него. Диагностика
сохраняется и при ошибке компиляции, отмене или таймауте. Готовые входы удаляются
после остановки VM; гостевые временные копии удаляются после операции.

Собственные тесты runner используют настоящий subprocess-протокол поддельного
Tart, без VM и без рабочего стола:

```sh
python3 -m unittest discover -s apps/macos -p 'test_desktop_vm.py' -v
```

`task test:macos` и `task verify` сохраняют диагностику VM в собственном каталоге
`reports/local/<run-id>/macos/`. Отсутствие VM означает ошибку обязательного этапа.
Обычные Foundation/Core-проверки без UI можно выполнять на хосте отдельно:
`swift test --package-path apps/macos --filter AlbertCoreTests`.

Справка Tart: [общие каталоги](https://github.com/openai/tart/blob/main/docs/quick-start.md#mounting-directories),
[параметры run](https://github.com/openai/tart/blob/main/Sources/tart/Commands/Run.swift),
[автоматическая очистка кеша](https://tart.run/faq/#automatic-pruning).
