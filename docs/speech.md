# Голосовые сообщения и Nemotron STT

[К содержанию](README.md)

Jarvis распознаёт готовые Telegram voice/audio через отдельный CPU-сервис `stt`. В Compose он подключён к `http://stt:8080/v1`; реальную `.env` для этого менять не требуется. Вне Compose STT включается только при заданном `STT_BASE_URL`. Разговорная LLM и её ключ независимы от STT.

## Контейнер и API

Образ собирает официальный [NeMo-Speech.cpp](https://github.com/NVIDIA/NeMo-Speech.cpp) из коммита `2bdfb03b38d5e3b0fa55aeb91a079a9f57385373` без GPU. Веса не включены в образ. При явном запуске bootstrap загружает GGUF в `container_data/stt/`, проверяет размер и SHA-256 и атомарно переименовывает временный файл. Существующие веса проверяются на каждом старте; повреждённый файл автоматически не заменяется.

- Модель: `nvidia/nemotron-3.5-asr-streaming-0.6b`, Q8_0.
- Ревизия: `ea30d66debe3740a08b573244286791d423d6b3e`.
- Файл: `nemotron-3.5-asr-streaming-0.6b.q8_0.gguf`, 742090464 байта.
- SHA-256: `3fc991d3badad7277c11030a7519832cddaf2057aafed6d4b25147e953a070b1`.

HTTP-обёртка принимает `POST /v1/audio/transcriptions`: multipart `file`, `model`, `response_format=json`. Ответ — `{"text":"..."}` с дополнительными диагностическими `duration_seconds`, `decode_ms`, `inference_ms`. Обязательное `model` должно совпадать с `STT_MODEL`: это имя одной загруженной модели, не переключатель весов.

FFmpeg внутри контейнера преобразует OGG/Opus и другие разрешённые аудиоконтейнеры в WAV PCM16 mono 16 kHz. Сетевые протоколы и плейлисты декодеру запрещены. Затем вызывается штатный WAV endpoint NeMo-Speech.cpp на `127.0.0.1:8081`, язык `ru-RU`. Наружу контейнера доступен адаптер на 8080, без публикации порта на хосте. `/ready` и `/healthz` проверяют готовность native сервера.

Поддерживается файловое распознавание с итоговым текстом. Потоковый диалог, частичные результаты, diarization, timestamps слов и выбор языка не входят в этот контракт. Совместимость файлового API не означает совместимость Realtime-протоколов.

## Активация после согласования

Изменения кода и Compose не меняют запущенный MVP. Следующие команды предназначены для отдельно согласованной активации из основной установки после переноса изменений. Не запускай второй Jarvis из рабочего дерева с тем же Telegram-токеном.

```sh
docker compose build stt jarvis
docker compose up -d stt
docker compose ps stt
```

Первый запуск загружает около 742 MB весов и прогревает модель. Дождись `healthy`; стартовый период healthcheck — 15 минут. Проверка без Telegram:

```sh
docker compose exec stt python3 -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8080/ready').read().decode())"
```

После готовности STT отдельно пересоздай Jarvis для нового кода и настроек:

```sh
docker compose up -d --no-deps jarvis
```

Bootstrap подготавливает владельца каталога `/models`, затем сбрасывает привилегии. Для офлайн-развёртывания заранее размести проверенный файл указанной ревизии и задай `STT_DOWNLOAD_MODEL=false`.

| Настройка | Значение и смысл |
| --- | --- |
| `STT_BASE_URL` | В Compose по умолчанию `http://stt:8080/v1`; явно пустое значение отключает клиент. Вне Compose по умолчанию пусто. |
| `STT_MODEL` | `nemotron-3.5`, имя единственной модели API. |
| `STT_API_KEY` | Необязательный отдельный Bearer key. |
| `STT_REVISION` | `ea30d66d-q8-nemo2bdfb03b-ru-pcm16-v1`, профиль кэша; менять вместе с весами, runtime, языком или обработкой. |
| `STT_DOWNLOAD_MODEL` | Разрешает загрузку отсутствующих весов при старте контейнера. |
| `STT_CPUS` | Начальное ограничение CPU: 2. |
| `STT_THREADS` | Начальное `OMP_NUM_THREADS`: 2, не общий предел всех native потоков. |
| `STT_MEMORY_LIMIT` | Начальный предел: 3g; непроверенный бюджет, не RAM-минимум модели или всего Jarvis. |

Отключение клиента не удаляет сервис `stt` из Compose. Для внешнего STT задай его URL, модель и профиль; локальный контейнер запускать не требуется. Прежний `LLM_TRANSCRIPTION_MODEL` больше не используется.

## Конвейер и надёжность

Durable Telegram inbox → `PrepareAudio` → оригинал в S3 → `TranscribeAudio` → сохранённый текст → `Prepare` → обычный агентский цикл. Связь артефакта с сессией сохраняется до inference. Бинарное аудио не передаётся в истории Temporal. Полный текст хранится отдельно от ограниченного контекста LLM. Автор берётся из Telegram-события; область личного чата, группы и топика сохраняется. STT не определяет личность говорящего.

Успешный кэш в PostgreSQL учитывает область разговора, SHA-256 оригинала и профиль endpoint/модели/ревизии. Повтор `Prepare`, Activity или новый turn используют сохранённый результат. Между разговорами кэш не разделяется; это runtime-данные, не Markdown-память агента.

Двухминутный продлеваемый lease предотвращает конкурирующие попытки. Commit проверяет владельца; после смерти worker lease истекает. Повтор после успешного commit кэша восстанавливает результат вложения без inference. Окно между завершением HTTP и commit остаётся: сервер не предоставляет exactly-once вычисления. Последовательность новых Activities включается Temporal version marker на turn, сохраняя replay прежних историй.

## Ограничения и отмена

- Оригинал — до 20 MiB, как в Telegram-клиенте и S3. Запись — до 5 минут; проверяются метаданные и фактически декодированная длительность. Более длинный исходник в пределах 20 MiB сохраняется без STT. WAV ограничен 20 MiB; пять минут занимают около 9,6 MB.
- Декодирование — до 45 секунд, HTTP inference — до 10 минут. Activity — до 12 минут на попытку, до 30 минут с очередью и retry, до 5 попыток. Временные сбои повторяются; постоянные HTTP 4xx, кроме 408/429, не повторяются.
- Worker `${TEMPORAL_TASK_QUEUE}.stt` выполняет одну Activity одновременно. Адаптер также допускает один запрос и возвращает 503 при занятости. Время ожидания ограничено; отдельного ограничения числа записей durable inbox пока нет.
- Второе обычное сообщение не отменяет STT: оно учитывается вместе с расшифровкой перед следующим содержательным действием. Другие разговоры используют отдельные обычные Activity-слоты.
- `/stop` отменяет turn и decoder/клиентский HTTP. Heartbeat доставляет отмену Activity. Поздний результат не запускает LLM отменённого turn; входящие сообщения не возвращаются в обработку.
- Native API не обещает прекращения inference при разрыве соединения. Адаптер удерживает слот до ответа/timeout native вызова даже после отключения клиента. Немедленное освобождение CPU не гарантируется.

При отключённом STT, ошибке или пустом результате агент получает явный статус и может попросить текст. Исходник остаётся сохранённым при успешном скачивании; сбой скачивания/сохранения обрабатывается как ошибка turn.

## Инспектор и проверка

Раздел «Аудио» показывает оригинал, автора, полный текст, состояние, ожидание, время и реальные попытки STT. Использование кэша отмечено отдельно, без фиктивной трассы. Тексты остаются в PostgreSQL/S3; HTTP-ключи и бинарное аудио в трассы не попадают. Автоматическая очистка кэша пока не настроена.

Вкладки доступны стрелками и Home/End. На плеере Space запускает/приостанавливает аудио; Enter открывает подробности попытки, Escape закрывает их с возвратом фокуса. Автообновление приостанавливается при воспроизведении.

```sh
go test -race ./...
go vet ./...
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH='/path/to/chromium' ./docs/node_modules/.bin/playwright test -c internal/inspector/playwright.config.mjs
```

SQL-контракты требуют отдельную временную PostgreSQL через `JARVIS_TEST_DATABASE_URL`, никогда рабочую базу. Тесты декодирования используют синтетический OGG и подставной native endpoint. Без FFmpeg на хосте их можно выполнить внутри собранного STT-образа с тестовым Go-бинарником для архитектуры образа. Ни веса, ни Telegram для этого не нужны.

Эти проверки не измеряют качество Nemotron. Отдельный эксперимент на целевом Linux CPU должен сравнить одинаковые русские записи с ручными эталонами: WER/CER, смысловые ошибки имён/чисел/отрицаний, холодный старт, время OGG → текст и пик RAM. Результатов таких замеров пока нет.
