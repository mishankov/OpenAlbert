# Инспектор сессий

[К содержанию](README.md)

## Как открыть

Локальный адрес: [http://localhost:8080/inspect/](http://localhost:8080/inspect/). Инспектор встроен в Go-приложение, включён в Docker-образ и запускается вместе с OpenAlbert. Отдельный frontend-сервис и сборка JavaScript для работы не нужны.

Это интерфейс только для чтения всех разговоров этой инсталляции, включая личные и групповые. Здесь нет отправки сообщений, изменения памяти и управления задачами. Сетевой доступ определяется публикацией порта в Compose; приложение не ограничивает Host, Origin или Sec-Fetch-Site. Логин не требуется. По умолчанию порт опубликован только на loopback.

Для доступа из доверенной локальной сети укажи LAN-адрес сервера в `ports` сервиса `openalbert`:

```yaml
ports:
  - "192.168.1.31:8080:8080"
```

После пересоздания контейнера инспектор доступен по `http://192.168.1.31:8080/inspect/`. `INSPECTOR_PUBLIC_URL` задаёт этот адрес для ссылок бота и не управляет доступом. Отдельный прокси для LAN не нужен. Устройства с сетевым доступом к порту могут читать все данные инспектора.

## Поиск и просмотр

Слева — сессии в порядке создания от новых к старым. Поиск находит ID, название разговора, текст сообщений, аргументы инструментов и резюме. Фильтры позволяют выбрать активные или закрытые сессии и источник: сообщение, длительная задача, инициатива. Пагинация не ограничивает просмотр последними 50 сессиями.

Каждая сессия имеет постоянную ссылку вида `/inspect/#/session/<id>`. Внутри доступны:

- **Хронология** — компактные строки пользовательских сообщений, ответов модели и инструментальных действий. Голосовое сообщение выделено цветом и подписью: видны автор, исходное аудио с плеером, подпись пользователя и автоматическая расшифровка. Следом идёт отдельная раскрываемая строка **«Распознавание речи»** со статусом, моделью, временем и реальными попытками. Кэш отмечен без вымышленного вызова. Ожидание и ошибки видны до сохранения подготовленного сообщения; после его появления голосовое не дублируется. Вызов тула и его результат объединены в одну раскрываемую строку; результат повторно отдельным блоком не показывается. При раскрытии аргументы и результат располагаются рядом. Кнопки исходных записей открывают JSON в боковой панели с ролями, автором, ключом мутации и `tool_call_id`. Счётчик вкладки показывает число исходных записей, а не визуальных строк и операций STT.
- **Модель** — таблица запросов агентского цикла и последующего анализа сессии. Подробности содержат снимок контекста, system prompt, описания и схемы доступных инструментов, ответ провайдера, число токенов, время начала и завершения, номер попытки и ошибку. Сюда попадают и ответы, отброшенные после поступления нового сообщения.
- **Доставка** — реальные записи outbox с адресатом, текстом, количеством попыток и состоянием: в очереди, отправляется, доставлено, ошибка либо неизвестный исход. Внутренний финальный текст не считается доставленным сообщением.
- **Запуски** — завершённые шаги обработки внутри сессии, причина завершения, токены, число модельных и инструментальных вызовов, финальный текст и сохранённое состояние. Здесь же можно раскрыть результат анализа закрытия сессии: кандидаты в память и данные проверки.
- **Артефакты** — файлы и скриншоты, на которые ссылается история этой сессии; изображения можно посмотреть непосредственно в инспекторе.

Ссылка `/inspect/#/session/<id>?trace=<trace_id>` сразу открывает конкретный вызов. Такие ссылки находятся в поле `inspector_url` событий VictoriaLogs. Они сохраняются при перезагрузке страницы; `Escape` закрывает панель, оставляя текущую сессию. Если запись не найдена, панель показывает ошибку, а сессия остаётся доступной.

Кнопка **«Логи»** открывает VictoriaLogs в новой вкладке с [фильтром обычного просмотра](observability.md): быстрые успешные запросы Temporal UI скрыты, HTTP-ошибки и медленные запросы видны. Поиск и открытая сессия инспектора сохраняются. При нестандартной публикации VictoriaLogs используй его фактический адрес; встроенная ссылка рассчитана на тот же хост и порт 9428.

Список и открытая сессия обновляются каждые 10 секунд, пока вкладка видима. Во время чтения подробностей вызова автоматическое обновление приостанавливается. Поисковый запрос и раскрытые записи сохраняются при обновлении. Основные сведения о сессии собраны в компактной закреплённой шапке; длинный текст раскрывается в строке, а JSON и контекст — в боковой панели. Длинные сессии загружаются частями по 200 сообщений с продолжением до конца истории.

## Память

Раздел **Память** в верхней панели открывает `/inspect/#/memory`. Выбери личный разговор, группу или топик: записи разных разговоров не смешиваются. При переходе из открытой сессии впервые выбирается её разговор. Выбранный разговор сохраняется в ссылке после смены селектора: `/inspect/#/memory?conversation_id=<id>`.

Список показывает текущие записи от недавно обновлённых к старым; при одинаковом времени они упорядочены по ID. Есть поиск по тексту, ID, источнику, цитате и Telegram ID участника, а также фильтр по типу: профиль, предпочтение, факт, эпизод, предположение. Поиск не учитывает регистр и требует все слова запроса в одной записи. Записи загружаются страницами по 100; ограничение поиска агента в 50 записей здесь не применяется. Кнопка «Ещё записи» позволяет дойти до конца списка.

Над списком можно раскрыть **«Личность SOUL.md»** — полный текущий текст имени, характера и правил общения OpenAlbert. Этот файл общий для всех разговоров и доступен даже до появления первой сессии. Инспектор читает настроенный `SOUL_FILE`, если он задан, иначе `SOUL.md` из каталога знаний. Текст обновляется кнопкой «Обновить» или `Alt+R`; раскрытие с клавиатуры — `Enter` или `Space`.

Если у разговора есть собранный профиль `USER.md`, его можно раскрыть над списком. Поиск и фильтр относятся к исходным записям и не меняют показываемый профиль. Нажатие на запись или `Enter` открывает полный текст, тип, время обновления, ID и исходный JSON в боковой панели. Для фактов участников видны Telegram ID, ID сообщения и цитата-основание, когда они сохранены. Источник открывается как сессия инспектора; старая или удалённая сессия может быть недоступна.

Память обновляется вручную кнопкой «Обновить» или `Alt+R`, начиная с первой страницы. Поиск, тип и разговор сохраняются при обновлении и переходах между разделами. `⌘K` / `Ctrl+K` переводит фокус в поиск, `Escape` закрывает подробности и возвращает фокус на запись. Здесь доступен только просмотр текущей памяти; история удалённых записей не показывается.

## Файлы MinIO

Раздел **Файлы** в верхней панели открывает `/inspect/#/files`. Он читает объекты непосредственно из настроенного `S3_BUCKET`, в том числе файлы без записи в PostgreSQL и без привязки к сессии. Отображаются имя, ключ объекта, размер и время изменения. Для артефактов OpenAlbert исходное имя берётся из метаданных MinIO; при отсутствии этих метаданных показывается имя из ключа объекта.

Фильтр «Префикс ключа» ограничивает список началом полного ключа, например `artifacts/`. Объекты отсортированы по времени изменения в MinIO: сначала новые, как указано над галереей. Сортировка охватывает весь бакет с учётом фильтра; при одинаковом времени порядок определяется ключом объекта. Следующие 100 файлов загружаются кнопкой «Ещё файлы». Фильтр сохраняется при переходе между разделами и обновлении. Галерея обновляется вручную кнопкой «Обновить» или `Alt+R`; обновление начинает список с первой страницы.

PNG, JPEG, GIF, WebP и AVIF видны сразу в галерее: крупные превью показывают изображение целиком, без обрезки; кадры вне экрана подгружаются по мере прокрутки. Под каждым файлом показаны имя, время изменения, размер и ключ. Если изображение не загрузилось, карточка сообщает об ошибке и остаётся доступной для открытия и скачивания.

Нажатие на карточку или `Enter` открывает увеличенное изображение и подробности в боковой панели. Для текстовых MIME-типов, JSON, XML и YAML доступен текстовый предпросмотр UTF-8 до 256 КБ с явной отметкой об обрезке. HTML и SVG показываются исходным текстом. Другие форматы можно скачать. Кнопка «Скачать» доступна для любого файла; содержимое передаётся через backend, ключи доступа к MinIO браузеру не передаются. Здесь нет загрузки, изменения и удаления объектов.

Раздел **Аудио** показывает сохранённый оригинал, автора, полный текст распознавания, модель, время и ошибки отдельных попыток. Он доступен и до завершения подготовки сообщения. Использование кэша отмечается без нового вымышленного вызова. При фокусе на плеере Space запускает/приостанавливает аудио; автообновление приостанавливается во время воспроизведения. Подробнее — [голосовые сообщения](speech.md).

## Что известно о размышлениях

Инспектор показывает только данные, действительно возвращённые API. Текстовые поля `reasoning_content` или `reasoning`, если провайдер их вернул, сохраняются отдельно от обычного ответа и отображаются как «Размышления, возвращённые провайдером». Это может быть предоставленная провайдером сводка; скрытые внутренние рассуждения модели недоступны.

Включение инспектора не включает специальный thinking-режим и не меняет параметры генерации. Исторические рассуждения, которые приложение раньше не сохраняло, восстановить нельзя.

## Хранение и ограничения

Сообщения хранятся в `openalbert_messages`, а трассы вызовов — в `openalbert_traces` в PostgreSQL. Снимок содержит данные приложения перед вызовом, без HTTP-заголовков и ключа API. Бинарные данные изображений в снимках заменены отметками, чтобы не копировать их при каждом шаге; артефакты остаются в S3. Пользовательский текст может содержать конфиденциальные сведения и намеренно доступен локальному инспектору.

Один реальный Activity attempt имеет одну трассу с переходом из начатого состояния в завершённое или ошибку. Ответ из существующего checkpoint не создаёт новый вымышленный вызов. Если процесс аварийно завершился, начатая запись может остаться без результата: такое состояние само по себе не доказывает, что операция ещё выполняется. Ошибка сохранения диагностической трассы не меняет результат инструментального действия и отмечается операционным предупреждением.

Для прежних сессий инспектор читает сообщения, результаты инструментов, checkpoints модели, итоговые состояния запусков и outbox. Отсутствующий в базе приложения исходный контекст, название прежней модели, размышления и точное время отдельных сообщений не придумываются: интерфейс явно отмечает исторические записи. Время обычных сообщений — время сохранения в приложении. У голосовых при наличии исходного события показано время отправки в Telegram; если оно недоступно, используется время сохранения. Состояние доставки показывается отдельно. Полные данные некоторых старых Activities могут оставаться в истории Temporal; инспектор их пока не импортирует.

Подробные тексты остаются в PostgreSQL и не добавляются к широким событиям VictoriaLogs. Срок хранения трасс сейчас совпадает со сроком хранения базы приложения; автоматическая очистка не настроена. Резервная копия `container_data/postgres` включает и эти записи.

## Клавиатура и проверки

- `⌘K` на macOS или `Ctrl+K` — перейти к поиску сессий, поиску памяти или к фильтру файлов в текущем разделе, сохранив введённый текст.
- `Alt+R` — обновить данные, то же действие, что кнопка «Обновить».
- `Alt+L` — открыть логи с готовым фильтром в новой вкладке, то же действие, что ссылка «Логи». Не срабатывает при загрузке данных или в открытой панели подробностей.
- `Tab` и `Enter` — открыть сессию, раскрыть событие, строку распознавания или подробности вызова. На плеере `Space` запускает и приостанавливает аудио.
- Стрелки влево/вправо, `Home` и `End` — переключить раздел сессии из панели вкладок.
- `Escape` — закрыть подробности и вернуть фокус на открывшую их кнопку.
- `Tab` и `Enter` в разделе файлов — выбрать файл, открыть предпросмотр, загрузить следующую страницу или скачать файл с соответствующей кнопки.
- `Alt+Shift+S` в открытой панели файла — скачать файл, то же действие, что кнопка «Скачать».

Сочетания не срабатывают во время IME-композиции и при удержании клавиши. В открытых подробностях доступны закрытие и скачивание файла; поиск и обновление приостановлены. Проверка физического `event.code` сохраняет работу сочетаний в русской раскладке. Обновление учитывает занятость; открытый диалог удерживает клавиатурный фокус.

Проверки backend и хранения:

```sh
go test -race ./...
go vet ./...
```

Для SQL-контракта нужна отдельная тестовая PostgreSQL и `OPENALBERT_TEST_DATABASE_URL`. Не используй рабочую базу для контрактных тестов.

Браузерные проверки интерфейса используют существующий Playwright из `docs/package.json` и локальные фикстуры, без настоящего Telegram или LLM:

```sh
npm ci --prefix docs
./docs/node_modules/.bin/playwright install chromium
./docs/node_modules/.bin/playwright test -c apps/backend/internal/inspector/playwright.config.mjs
```

Если браузер уже установлен отдельно, путь можно передать через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.
