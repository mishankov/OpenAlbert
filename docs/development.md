# Запуск и разработка MVP

[К содержанию](README.md)

MVP работает через Telegram; веб-инспектор показывает сессии, память, файлы и диагностику. Backend написан на Go (`CGO_ENABLED=0`) и включает встроенный оркестратор, встроенную pure-Go SQLite (`DATA_DIR/openalbert.db`, режим WAL), локальное хранилище артефактов (`DATA_DIR/artifacts`) и встроенный журнал событий `openalbert_logs`. Внешние серверы баз данных, очередей, S3 и логов не требуются. Отдельный Linux-компьютер пользователя подключается по SSH. Клиентский HTTP API описан в [client-api.md](client-api.md).

Этот документ описывает локальную разработку через `deploy/compose.local.yaml` (собирает образы `openalbert`, `stt`, `tts` и `backup` из исходников) и прямой запуск бинарника `./openalbert` без Docker. Установка готовых образов из GHCR и локальная публикация описаны в [руководстве публикации](deployment.md). `deploy/compose.yaml` запускается отдельно и не требует сборки на сервере.

Полный набор проверок и сборок запускается через [Task](local-checks.md):
`task check`, `task test`, `task images`, `task verify`.

## Первый запуск в Docker Compose

Нужны Docker Engine с Compose 2.24.0+ и свободный локальный порт `8080`. Никаких дополнительных портов для БД, очередей или логов не требуется.

```sh
cp .env.example .env
cp deploy/models.example.toml models.toml
```

Заполни `.env`: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_USER_IDS`, `LLM_API_KEY`. В `models.toml` задай модель, endpoint, возможности и лимиты выбранного профиля; пример направляет роли на одну модель. Дополнительные ключи профилей можно задать в необязательном `models.env` рядом с `.env` (`chmod 600 models.env`); Compose загрузит его автоматически. Подробности — [маршрутизация моделей](model-routing.md). Для старта API-поиск не требуется: оставь `EXA_API_KEY`, `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` пустыми. Без них агент читает публичные ссылки через `web_read` и браузерные инструменты, а `web_search` отсутствует в доступных инструментах. Чтобы подключить поиск позже, заполни `EXA_API_KEY` (для Exa Search, по умолчанию `EXA_MONTHLY_BUDGET_USD=10`) или обе переменные `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` (для Yandex); если заданы ключи обоих провайдеров, явно укажи `WEB_SEARCH_PROVIDER=exa` или `WEB_SEARCH_PROVIDER=yandex`. Файл `.env` игнорируется Git.

После настройки запусти стек (по умолчанию `.env.example` включает `COMPOSE_PROFILES=local-stt` — запускаются `openalbert` и `stt`):

```sh
docker compose --project-directory . -f deploy/compose.local.yaml up -d --build
```

Для **минимального режима одного контейнера** (без локального распознавания речи) задай в `.env` пустые значения `COMPOSE_PROFILES=` и `STT_BASE_URL=` — запустится только `openalbert`.

В `TELEGRAM_ALLOWED_USER_IDS` указываются числовые Telegram ID разрешённых пользователей через запятую. Пустой список запрещает запуск. По умолчанию бот принимает только личные сообщения от этих пользователей. Для групп нужно дополнительно указать отрицательные ID групп в `TELEGRAM_ALLOWED_GROUP_IDS`; в разрешённых группах принимаются сообщения всех обычных участников, доставленные Telegram. При `TELEGRAM_ALLOW_BOT_MESSAGES=true` в этих группах также принимаются сообщения ботов: текст, Rich Messages, вложения и команды проходят обычную обработку. Личные сообщения ботов по-прежнему игнорируются. Для доставки сообщений между ботами включи Bot-to-Bot Communication Mode в BotFather, а для всех групповых реплик также отключи Group Privacy либо назначь бота администратором ([правила Telegram](https://core.telegram.org/bots/features#bot-to-bot-communication)). Список `TELEGRAM_ALLOWED_USER_IDS` ограничивает личные чаты. Группы видят только свой контекст. Личный чат владельца может читать сохранённые групповые обсуждения через инструменты истории и памяти; обратный доступ запрещён кодом.

Инспектор сессий доступен на `http://localhost:8080/inspect/` ([возможности и ограничения](inspector.md)), health endpoint — на `http://localhost:8080/healthz`. Порт опубликован только на loopback-интерфейсе (`127.0.0.1:8080`); для доступа из другой машины потребуется отдельная настройка публикации, аутентификации или TLS.

Самодиагностика `logs_search` работает из коробки: операционные события пишутся во встроенную таблицу SQLite `openalbert_logs` (срок хранения 30 дней). Инструмент доступен в личном чате и запланированных задачах владельца (`TELEGRAM_OWNER_USER_ID`, по умолчанию первый разрешённый пользователь); группы и инициативные проверки доступа не имеют.

Не запускай два экземпляра Telegram poller с одним токеном. Для смены модели измени профиль или привязку роли в `models.toml`, при необходимости обнови ключ в `.env`, затем пересоздай приложение:

```sh
docker compose --project-directory . -f deploy/compose.local.yaml up -d --force-recreate openalbert
```

Для OpenCode Go укажи в профиле `base_url = "https://opencode.ai/inference/go/openai/v1"`, фактический ID модели и `options.session_header = "x-opencode-session"`. Для DeepSeek thinking с историей tools включи `options.include_reasoning_content = true`. Настройки задаются явно: адаптер не выбирает протокол по имени модели или адресу. [Поля и примеры TOML](model-routing.md).

Chromium установлен в образ OpenAlbert и запускается по необходимости. Для запуска Go-бинарника вне Docker установи Chromium, задай `BROWSER_EXECUTABLE` или отключи браузер через `BROWSER_ENABLED=false`. Поддерживаются публичные сайты без входа в аккаунты. Ограничения контейнера и sandbox описаны в [разделе браузера](browser.md).

## Настройки запуска

Полный пример находится в `.env.example`. Все переменные также работают при запуске голого бинарника `./openalbert` без Docker.

| Настройка | Назначение |
| --- | --- |
| `DATA_DIR` | Корневой каталог состояния приложения (в Compose `/data`, вне Docker по умолчанию `./data`). Производные пути по умолчанию: `openalbert.db`, `artifacts/`, `knowledge/`, `chatgpt/credentials.json` |
| `DATABASE_PATH`, `ARTIFACTS_DIR`, `KNOWLEDGE_DIR`, `OPENAI_TOKEN_STORE` | Необязательные переопределения путей внутри `DATA_DIR` |
| `TELEGRAM_BASE_URL` | Необязательный корень Bot API server; пусто — официальный Telegram endpoint |
| `TELEGRAM_BOT_TOKEN` | Обязательный токен Telegram Bot API |
| `TELEGRAM_ALLOWED_USER_IDS` | Обязательный список разрешённых пользователей |
| `TELEGRAM_OWNER_USER_ID` | Владелец, чей личный чат может читать историю и память групп. ID должен входить в список разрешённых; по умолчанию первый ID в нём |
| `TELEGRAM_ALLOWED_GROUP_IDS` | Разрешённые группы; пусто — только личные чаты |
| `TELEGRAM_WORKSPACE_GROUP_ID` | Необязательная супергруппа владельца с форум-топиками; пусто отключает режим workspace |
| `TELEGRAM_ALLOW_BOT_MESSAGES` | `false` по умолчанию; `true` принимает сообщения ботов в разрешённых группах наравне с сообщениями людей |
| `TELEGRAM_WIDGETS` | Режим виджетов Telegram: `auto` (по умолчанию), `on` или `off` |
| `LLM_CONFIG_FILE` | Обязательный путь к TOML с профилями и маршрутами; вне Docker, например `./models.toml` |
| `LLM_CONFIG_HOST_FILE` | Путь к TOML на хосте для Compose, по умолчанию `./models.toml`; внутри контейнера всегда `/etc/openalbert/models.toml` |
| `LLM_API_KEY` | Пример переменной ключа, передаваемой Compose; имя выбирается в `api_key_env` профиля |
| `OPENAI_AUTH_MODE`, `OPENAI_SIWC_MODEL`, `OPENAI_LANE_COOLDOWN` | Режим авторизации (`profiles` по умолчанию) и настройки совместимости плана ChatGPT. [Подробнее](chatgpt-plan-usage.md) |
| `COMPOSE_PROFILES` | Включаемые необязательные сервисы Compose: `local-stt`, `local-tts`, `backup`; пустое значение запускает только `openalbert` |
| `STT_BASE_URL`, `STT_MODEL`, `STT_REVISION`, `STT_API_KEY` | Независимый файловый STT; в Compose по умолчанию `http://stt:8080/v1`, вне Docker пусто. [Настройки и активация](speech.md) |
| `TTS_BASE_URL`, `TTS_MODEL`, `TTS_VOICE`, `TTS_API_KEY` | Необязательный синтез голосовых ответов (Piper или внешний совместимый API); по умолчанию пусто |
| `WEB_SEARCH_PROVIDER` | Необязательный выбор провайдера поиска (`exa` или `yandex`); пусто — автовыбор единственного настроенного провайдера |
| `EXA_API_KEY`, `EXA_SEARCH_URL`, `EXA_MONTHLY_BUDGET_USD` | Необязательный доступ к Exa Search API (`EXA_SEARCH_URL` пусто — `https://api.exa.ai/search`, бюджет по умолчанию `10`) |
| `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, `YANDEX_SEARCH_URL` | Необязательный доступ к Yandex Search API; ключ и folder ID заполняются вместе или остаются пустыми |
| `BROWSER_ENABLED` | Браузерные инструменты, по умолчанию `true`; образ содержит Chromium |
| `BROWSER_EXECUTABLE` | Необязательный путь к Chromium; пусто — поиск в `PATH` |
| `BROWSER_NO_SANDBOX` | Compose: `true` для Docker Desktop; вне Docker по умолчанию `false` |
| `SOUL_FILE` | Необязательный отдельный файл характера; по умолчанию `SOUL.md` в `KNOWLEDGE_DIR` |
| `SESSION_IDLE_TIMEOUT` | Время без новых сообщений до закрытия сессии, по умолчанию `30m` |
| `CODING_SESSION_STALE_TIMEOUT` | Время без новой активности до автозакрытия осиротевшей активной `coding:*`-сессии, по умолчанию `24h`; `0` отключает автозакрытие |
| `MAX_AGENT_STEPS` | Максимум исследовательских шагов одного агентского запуска, по умолчанию `100`; для интерактивного запроса после лимита разрешён ещё один завершающий вызов модели только с `send_message` |
| `TASK_MIN_INTERVAL` | Минимальный период повторяющихся задач, по умолчанию `5m` |
| `INITIATIVE_INTERVAL` | Период фоновой инициативы, по умолчанию `30m`; `0` отключает её |
| `MEMORY_CONSOLIDATION_INTERVAL` | Период автономной консолидации памяти, по умолчанию `24h`; `0` отключает расписание |
| `HTTP_ADDR` | Listen-адрес HTTP-сервера (health endpoint, инспектор и клиентский API), по умолчанию `127.0.0.1:8080` (в Compose задаётся `:8080` внутри контейнера при публикации на `127.0.0.1`) |
| `INSPECTOR_PUBLIC_URL` | Базовый URL инспектора для диагностических ссылок, по умолчанию `http://localhost:8080/inspect/` |
| `BACKUP_STATE_DIR` | Каталог статуса резервирования (в Compose `/data/backup-state`, смонтирован read-only из `./backup-state`); пустое значение отключает интеграцию |
| `COMPUTER_SSH_ADDRESS`, `COMPUTER_SSH_USER`, `COMPUTER_SSH_PASSWORD`, `COMPUTER_SSH_KEY_FILE` | Необязательное SSH-подключение к компьютеру пользователя. [Подробнее](computer.md) |
| `DESKTOP_API_TOKEN` | Bearer-токен клиентского HTTP API (минимум 32 байта); пусто отключает API |

Значения длительностей используют синтаксис Go: `30s`, `5m`, `6h`. По умолчанию SOUL хранится в `data/knowledge/SOUL.md` на хосте и `/data/knowledge/SOUL.md` в Compose. `SOUL_FILE` позволяет указать другой существующий файл; для работы `soul_update` файл и его каталог должны быть доступны процессу на запись. Публикация skills выполняется человеком после совместного обсуждения; агент сохраняет предложения отдельно.

После изменения `INITIATIVE_INTERVAL` или `MEMORY_CONSOLIDATION_INTERVAL` достаточно перезапустить приложение — встроенный планировщик подхватывает новые интервалы при старте.

## Как задать характер

Попроси бота в личном диалоге изменить имя или характер, например: «Теперь тебя зовут Атлас. Обнови SOUL.md». Агент прочитает актуальный текст и сохранит точечную правку. Можно также открыть `data/knowledge/SOUL.md` в редакторе и описать манеру общения, инициативу и принципы. При первом запуске отсутствующий SOUL создаётся из встроенного шаблона `apps/backend/internal/knowledge/templates/SOUL.md`.

Файл перечитывается при подготовке следующего запроса или фонового запуска. Пересобирать контейнер после правок не нужно. Уже выполняющийся шаг использует собранный ранее контекст. Изменять SOUL через инструмент можно только в личном интерактивном диалоге; в группах, задачах и проверках инициативы запись запрещена. Не редактируй файл вручную одновременно с выполняющейся правкой агента.

Память и опубликованные skills находятся в `data/knowledge/` в корне репозитория. Compose подключает `./data` к `/data` с правом записи. Каталог можно открыть обычным файловым менеджером или редактором; содержимое исключено из Git и Docker build context. Профиль разговора лежит в `data/knowledge/scopes/<хеш разговора>/USER.md`, заметки — в соседнем каталоге `memories/`, профили участников групп — в `participants/<Telegram ID>/`, правила групп — в `data/knowledge/groups/<Telegram chat ID>/GROUP.md`, навыки — в `data/knowledge/skills/`. На Linux каталог `./data` должен быть доступен пользователю контейнера с UID/GID `10001:10001`; при необходимости создай его заранее и назначь владельца. SOUL включён в тот же каталог и резервируется вместе с памятью.

## Работа с Go локально и запуск голого бинарника

Нужен Go 1.26. Внешняя инфраструктура в Docker для запуска приложения не требуется: SQLite, хранилище артефактов, оркестратор и журнал событий встроены в бинарник.

Сборка автономного статического бинарника (`CGO_ENABLED=0`) и запуск:

```sh
CGO_ENABLED=0 go -C apps/backend build -o ../../openalbert ./cmd/openalbert

DATA_DIR=./data \
LLM_CONFIG_FILE=./models.toml \
LLM_API_KEY='your-key' \
TELEGRAM_BOT_TOKEN='123:token' \
TELEGRAM_ALLOWED_USER_IDS='123456789' \
BROWSER_ENABLED=false \
./openalbert
```

Убери `BROWSER_ENABLED=false` (или укажи `BROWSER_EXECUTABLE`), если на хосте установлен Chromium и нужен встроенный браузер. По умолчанию автономный бинарник слушает `127.0.0.1:8080`.

Либо запуск напрямую через `go run` после загрузки `.env` в окружение процесса (само приложение не читает dotenv-файлы):

```sh
set -a
. ./.env
set +a
go run ./apps/backend/cmd/openalbert
```

Произвольные токены и пароли в shell-файле требуют корректного quoting; удобнее передать переменные средствами IDE или менеджера секретов. Секреты не передаются через аргументы командной строки и не выводятся в сообщения об ошибках конфигурации.

Локальные проверки Go и Compose:

```sh
sh tools/testing/go-modules.sh test ./...
sh tools/testing/go-modules.sh test -race ./...
sh tools/testing/go-modules.sh vet ./...
docker compose --project-directory . -f deploy/compose.local.yaml config -q
python3 tools/checks/check-compose.py
```

Проверки интеграций используют временную SQLite в `t.TempDir()` и локальные HTTP-имитаторы, чтобы не расходовать деньги и не отправлять сообщения настоящим пользователям. Проверка с реальными ключами — отдельный запуск владельца; успешные локальные проверки не доказывают доступность выбранного провайдера или поддержку конкретной моделью tool calls и изображений.

Для проверки инструкций поиска на выбранной модели есть отдельная opt-in оценка. Передай `LLM_CONFIG_FILE` и переменные ключей, указанные в TOML, через окружение процесса теста и запусти:

```sh
OPENALBERT_LIVE_RETRIEVAL_EVAL=1 go test ./apps/backend/internal/agent -run '^TestLiveRetrievalPrompts$' -v -count=1
```

Она вызывает реальную модель с рабочими инструкциями и описаниями инструментов, но использует временную память, задачи и outbox без доставки в Telegram. Проверяет использование готового профиля, поиск конкретного факта, восстановление после несовпадения написания названия, обзор последних записей и поиск расписания в задачах. В обычном `go test` оценка пропускается; результат зависит от выбранной модели и не гарантирует успех всех будущих запросов.

Отдельная оценка проверяет решение модели об отправке: прямой вопрос, приветствие и запрос статуса должны привести к явному `send_message`; просьба не отвечать, фоновая задача без новых данных и инициатива без новостей — завершиться без доставки. Она также использует изолированную память и outbox, реальные сообщения в Telegram не отправляет. С теми же TOML и переменными ключей:

```sh
OPENALBERT_LIVE_DELIVERY_EVAL=1 go test ./apps/backend/internal/agent -run '^TestLiveDeliveryPrompts$' -v -count=1
```

## Сквозная проверка контейнера

После сборки образа можно воспроизвести реальный путь сообщения без внешних ключей:

```sh
docker compose --project-directory . -f deploy/compose.local.yaml build openalbert
python3 tools/smoke/mvp-smoke.py
# Проверка с Yandex Search вместо Exa по умолчанию:
python3 tools/smoke/mvp-smoke.py --search-provider yandex
# Проверка запуска и работы без API-поиска (без Exa и без Yandex):
python3 tools/smoke/mvp-smoke.py --without-search
```

Требуется Python 3 и свободный порт 18089. Harness поднимает локальные имитаторы Telegram, OpenAI-совместимого API и поискового провайдера (по умолчанию Exa; `--search-provider yandex` переключает на Yandex, `--without-search` отключает оба провайдера), затем запускает настоящий контейнер OpenAlbert через временный Compose override с временным каталогом данных. В Docker Desktop контейнер обращается к ним через `host.docker.internal`; для другого Docker Engine передай `--host-address` с доступным из контейнера адресом хоста.

С флагом `--with-browser` smoke дополнительно открывает публичный `https://example.com` в настоящем Chromium, сохраняет скриншот в локальные артефакты и проверяет освобождение процесса после закрытия сессии. Telegram и модель остаются локальными имитациями.

Проверяются приём сообщения, агентский цикл во встроенном оркестраторе, поиск, автоматическое сохранение памяти, длительная задача, две доставки через outbox, закрытие сессий и анализ, сохранение текстового вложения в локальное хранилище артефактов, запись и чтение wide events в `openalbert_logs`. После перезапуска приложения тот же Telegram update воспроизводится повторно: модель и отправка не должны повториться, память должна сохраниться.

Проверка использует временный каталог данных и затем удаляет его вместе с тестовым контейнером. Если OpenAlbert уже работает, harness завершится без замены контейнера; сначала останови свой экземпляр. Для обычного запуска после smoke снова выполни `docker compose --project-directory . -f deploy/compose.local.yaml up -d openalbert` с собственными настройками.

## Логирование

Собственные операции OpenAlbert завершаются одним JSON wide event: идентификатор операции, контекст, результат, длительность, счётчики. Секреты, полные сообщения, prompts, содержимое файлов и сырые ошибки провайдеров не логируются. Такой подход основан на [Logging Sucks Бориса Тейна](https://loggingsucks.com/).

Широкие события сохраняются во встроенной таблице SQLite `openalbert_logs` (хранение 30 дней) и одновременно печатаются в stdout/stderr. В Compose контейнеры используют встроенный драйвер Docker `local` с ротацией (`max-size: 10m`, `max-file: 3`). Просмотр потока контейнера:

```sh
docker compose --project-directory . -f deploy/compose.local.yaml logs --tail=100 openalbert
```

Владелец может диагностировать работу через инструмент `logs_search` в личном чате или через веб-инспектор. Подробности полей и хранения описаны в [логировании](observability.md).

## Границы первой версии

Запускается одна реплика приложения: Telegram poller, доставка outbox, встроенный оркестратор, планировщик задач и HTTP-сервер работают в одном процессе. Входные данные MVP — текст, фотографии, текстовые документы и голосовые; сохранённые изображения можно повторно прочитать инструментом работы с артефактами. Голос распознаётся независимым STT endpoint (в Compose — необязательным CPU-контейнером Nemotron), голосовые ответы синтезируются необязательным Piper TTS. PDF и видео сохраняются как артефакты; извлечение содержимого из них пока не реализовано.

Поиск памяти лексический. Публикация skills требует ручного просмотра и принятия предложения; агент не меняет собственный характер. HTTP-интеграции проверены локальными имитаторами, включая сквозной запуск настоящего контейнера; реальные внешние ключи в проверках не использовались.

## Данные, остановка и резервная копия

Все постоянные данные приложения находятся в каталоге `./data` в корне репозитория и подключаются через bind mount. Вспомогательные каталоги расположены рядом на хосте. Все они исключены из Git и Docker build context.

| Каталог на хосте | Содержимое | Путь в контейнере |
| --- | --- | --- |
| `./data/` | `openalbert.db` (SQLite WAL), `artifacts/` (вложения), `knowledge/` (SOUL, профили, память, skills), `chatgpt/` (токены плана) | `/data` (`openalbert`), `/installation/data` (`backup`) |
| `./stt-models/` | Веса модели Nemotron STT (профиль `local-stt`) | `/models` (`stt`) |
| `./backup-config/` | Настройки и ключи внешнего S3-бакета для `backup` | `/etc/openalbert-backup` (ro) |
| `./backup-state/` | Состояние и события резервирования | `/installation/backup-state` (`backup`), `/data/backup-state` (ro в `openalbert`) |
| `./backup-work/` | Временная рабочая область сборки зашифрованного архива | `/var/lib/openalbert-backup` (`backup`) |
| `./computer/client/` | Необязательный приватный SSH-ключ для компьютера пользователя | `/data/computer` (ro в `openalbert`) |

`docker compose --project-directory . -f deploy/compose.local.yaml down`, включая вариант `-v`, не удаляет эти каталоги. Не удаляй `./data`, если данные нужно сохранить.

Для автоматического онлайн-резервирования без остановки OpenAlbert используй профиль `backup` (`VACUUM INTO`, шифрование age, загрузка в внешний S3) — подробности в [разделе резервного копирования](deployment.md#автоматические-копии-в-s3).

Для ручной файловой резервной копии останови приложение (или сними согласованный снимок SQLite через `sqlite3 data/openalbert.db "VACUUM INTO '/safe/backup/openalbert.db'"`) и скопируй `./data`, `.env`, `models.toml` (и `models.env`, если используется) с сохранением прав:

```sh
docker compose --project-directory . -f deploy/compose.local.yaml stop openalbert
# Скопируй ./data, .env и models.toml в защищённый каталог вне репозитория.
docker compose --project-directory . -f deploy/compose.local.yaml up -d openalbert
```

При перезапуске встроенный оркестратор продолжает незавершённые сессии, задачи и доставку из SQLite. Для внешних вызовов с неопределённым исходом повторная отправка может требовать отдельного решения: Telegram не гарантирует идемпотентную доставку сообщения при сетевом обрыве после приёма запроса.

## Ubuntu-компьютер Альберта

Компьютер создаётся и обслуживается пользователем отдельно. Основной Compose
не собирает и не запускает его; без `COMPUTER_SSH_ADDRESS` tools выключены.
Существующую Linux-машину можно подключить по SSH. Необязательный шаблон контейнера
копируется в отдельный пользовательский каталог и собирается там один раз.
Обновления Альберта не пересоздают этот компьютер и сохраняют установленное ПО.

Создание, подключение, перенос прежнего контейнера с сохранением системных изменений
и резервирование описаны в [руководстве компьютера](computer.md).
Изолированная проверка адаптера и независимого жизненного цикла: `task test:computer`.
