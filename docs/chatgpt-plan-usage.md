# Оплата через план ChatGPT

OpenAlbert может использовать лимит подписки ChatGPT через официальный Sign in with ChatGPT. Эти запросы расходуют общий allowance ChatGPT и Codex; возможен отдельный лимит приложения. API-ключ оплачивается отдельно.

## Режимы

- `OPENAI_AUTH_MODE=api_key` — значение по умолчанию, Chat Completions с маршрутами `chat`, `background` и `analysis` из [TOML-конфигурации](model-routing.md); ключи задаются через `api_key_env` профилей.
- `siwc` — только план ChatGPT. API-ключ не требуется; до входа запросы к модели не выполняются.
- `auto` — сначала план, затем API-ключ при ошибке доступности, лимита или отсутствии разрешения. Ключ обязателен. Ошибки маршрута, конфигурации и неподдерживаемых возможностей требуют исправления, а не смены оплаты.

`OPENAI_LANE_COOLDOWN=15m` задаёт локальную паузу перед повторной попыткой плановой оплаты. Это **не время сброса лимита ChatGPT**. Ошибка `subscription_sharing_user_not_eligible` отключает новые попытки до явного повторного входа. Перезапуск сбрасывает локальные счётчики и паузу.

`OPENAI_SIWC_MODEL` — начальный slug плановой модели, по умолчанию model ID профиля `chat` из TOML. В режиме `auto` можно использовать разных провайдеров и модели для API-ключа и плана. Выбранная затем в настройках модель ChatGPT сохраняется вместе с подключением и имеет приоритет над начальным значением. Каталог и отображаемые названия берутся из `/v1/models` текущего аккаунта, кэшируются на пять минут и сбрасываются при входе.

## Вход с VPS

1. Включите `siwc` или `auto` в конфигурации сервера и перезапустите backend.
2. В приложении macOS откройте «Подключение…» (`⌘,`) и нажмите **Continue with ChatGPT** (`⌘⇧L`). Альтернатива: `/chatgpt login` в личном Telegram-чате владельца; команда доступна в меню бота и возвращает ту же ссылку и кнопку.
3. В браузере подтвердите вход и разрешение использовать план. Браузер перейдёт на `http://127.0.0.1:1455/auth/callback?...`; на клиентской машине страница может не открыться. Скопируйте **полный адрес** из адресной строки.
4. Вставьте адрес в настройки macOS и нажмите «Завершить вход» (`⌘⇧Return`), либо отправьте `/chatgpt callback <полный адрес>` тому же боту. Срок попытки — десять минут; после рестарта начните новую попытку.
5. Выберите модель из каталога в настройках или через `/chatgpt models` и `/chatgpt model <slug>`.

В этом VPS-потоке сервер не открывает loopback listener: адрес переносится вручную, как предлагает issue #19. Публичный callback не добавляется. Callback проверяется по точному адресу и `state`, обменивается с исходным PKCE verifier один раз; ID token проверяется по OpenAI JWKS, issuer, audience, сроку, nonce и сохранённому subject. Повторный вход использует выданный `client_id`; смена аккаунта/воркспейса в этом MVP не поддерживается. Ссылки не содержат `id_token_hint`, чтобы не передавать токен через Telegram.

Если разрешение `chatgpt.tokens.use.direct` не выдано, вход сохраняется, а оплата планом остаётся выключенной. Используйте API-ключ или войдите снова с нужным разрешением. Приложение не запускает OAuth автоматически при 429/403/503. Если владелец явно повторяет вход после сохранённого входа без прямого разрешения, используется `prompt=consent`; обычный повторный вход не запрашивает согласие принудительно.

## Диагностика и хранение

Настройки macOS и `/chatgpt status` показывают выбранный режим, активную полосу, разрешение плана, модель, число попыток по каждой полосе с момента запуска, последний 429, локальную паузу и последний код ошибки/request ID. Проверяйте лимиты в [ChatGPT Usage](https://chatgpt.com/settings/usage).

На хосте путь задаёт `OPENAI_TOKEN_STORE` (по умолчанию `./container_data/chatgpt/credentials.json`). В Compose используется отдельный bind `container_data/chatgpt` → `/data/chatgpt`. Файл имеет права `0600`; обновление токенов атомарно, refresh сериализован, второй backend с тем же store не запускается. На Linux перед включением создайте каталог: `mkdir -p container_data/chatgpt`, затем `sudo chown 10001:10001 container_data/chatgpt` и `sudo chmod 700 container_data/chatgpt`. Токены переживают обычный рестарт и не включаются в текущий архив резервного копирования; после восстановления на другом хосте войдите заново.

Токены не возвращаются через Desktop API и не логируются. Callback-команды обрабатываются до PostgreSQL/Temporal и не попадают в разговор или prompt. При использовании Telegram сам callback проходит через Telegram; для передачи напрямую серверу используйте настройки macOS по защищённому соединению. Не пересылайте callback другим людям. ID-token hints не используются.

HTTP-ошибки сохраняют status, code, param, request ID и ограниченное тело ответа в `siwc.APIError` в памяти. В журнал идут только status/code/param/request ID, без тела и сообщений провайдера. Терминальная ошибка refresh удаляет негодные токены, сохраняя регистрацию и host ID; сетевой сбой их не удаляет.

Плановый транспорт использует только `https://api.openai.com/v1/responses`, `store:false`, `stream:true`, полную историю и developer-сообщения вместо system. Инструменты ядра передаются как function tools в namespace `openalbert`. Единственный успешный терминал — `response.completed`; частичные ответы и tool calls не исполняются. STT остаётся отдельным сервисом.

## Проверки

`task test:siwc` проверяет OAuth/JWKS, PKCE, scope, restart, refresh concurrency, allowlist тела Responses, SSE, fallback и owner-only команды на синтетических провайдерах. `task check` проверяет анализ Go и обе Compose-конфигурации. `task test:macos` запускает нативный keyboard flow и проверки клиента в управляемой Tart VM; Swift собирается на хосте.

Live consent и доступность preview для конкретного аккаунта проверяются отдельно реальным входом; синтетические тесты не подтверждают включение маршрута OpenAI для аккаунта.
