# Оплата через план ChatGPT

OpenAlbert может использовать лимит подписки ChatGPT через официальный Sign in with ChatGPT. Эти запросы расходуют общий allowance ChatGPT и Codex; возможен отдельный лимит приложения. API-ключ оплачивается отдельно.

## Профили: режим по умолчанию

`OPENAI_AUTH_MODE=profiles` выбирает оплату и модель отдельно для каждой роли через [TOML-конфигурацию](model-routing.md). Адаптер `openai_chatgpt` использует общий подписочный аккаунт и явный `model` профиля, `openai_chat_completions` — API-ключ и модель своего профиля. Можно направить `chat` и `analysis` в разные подписочные модели, оставив `background` на API. Несколько подписочных профилей используют один вход, а не несколько аккаунтов. Ошибка подписки не переключает запрос на API или другой профиль.

Для `openai_chatgpt` задай `model`, `capabilities`, `context_window_tokens`, `max_output_tokens`, `timeout`. При работе через прокси задай `base_url` и при необходимости `headers_env`. `max_output_tokens` задаёт локальный резерв входного контекста. OpenAI перечисляет допустимые поля запроса в [ограничениях preview](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations). Расчёт контекста использует настроенное окно модели, таймаут профиля применяется к запросу. Денежная оценка стоимости подписочных запросов не рассчитывается.

Модели выбираются в TOML с перезапуском приложения. `/chatgpt models` помогает узнать доступные slug. Глобальная команда `/chatgpt model` объясняет, как изменить профиль; HTTP API `PUT /api/v1/chatgpt/model` возвращает `409 config_managed` без изменения сохранённой модели. `OPENAI_SIWC_MODEL` и сохранённый старый выбор общей модели в этом режиме игнорируются. Подробный смешанный TOML и API-only пример — в [настройках моделей](model-routing.md).

## Подключение LLM Proxy на Raspberry Pi

1. Создай отдельного клиента для OpenAlbert в LLM Proxy. Сохрани его ключ как `OPENALBERT_PROXY_KEY` в закрытом `models.env` рядом с `models.toml`.
2. Добавь в существующий подписочный профиль `base_url = "https://proxy.example.com/v1"` с адресом своего прокси. Добавь таблицу `[profiles.<имя>.headers_env]` с записью `"X-LLM-Proxy-Key" = "OPENALBERT_PROXY_KEY"`. Остальные настройки бери из действующего профиля. Используй доверенный HTTPS endpoint. [Настройки прокси и заголовков](model-routing.md#прокси-и-http-заголовки) · [LLM Proxy](https://github.com/mishankov/llm-proxy)
3. В каталоге установки пересоздай backend командой `docker compose up -d --force-recreate openalbert`. Выполни `/chatgpt models`, затем отправь сообщение, которое использует этот профиль. Проверь, что OpenAlbert отвечает с сохранённым входом и запрос `/v1/responses` появился в LLM Proxy под созданным клиентом.

Запрос к `/responses` следует настройкам профиля, выбранного для роли. Команда `/chatgpt models` и HTTP API каталога используют настройки первого подписочного профиля среди маршрутов `chat`, `background`, `analysis` в этом порядке. Вход и обновление токенов идут напрямую на `auth.openai.com`.

## Совместимость старых режимов

Эти режимы требуют TOML только с адаптерами `openai_chat_completions`:

- `api_key` — API-профили ролей, ключи задаются через их `api_key_env`.
- `siwc` — только общий ChatGPT plan для всех ролей. API-ключ не требуется; до входа запросы к модели не выполняются.
- `auto` — сначала общий план, затем API-профиль роли при ошибке доступности, лимита или отсутствии разрешения. API-ключи обязательны. Ошибки маршрута, конфигурации и неподдерживаемых возможностей требуют исправления.

Только в этих старых `siwc`/`auto` `OPENAI_SIWC_MODEL` задаёт начальный общий slug (по умолчанию model ID профиля `chat`). Выбор через `/chatgpt model <slug>` сохраняется с подключением и имеет приоритет над начальным значением. В этих режимах приложение получает каталог текущего аккаунта напрямую с `https://api.openai.com/v1/models`. Каталог кэшируется на пять минут и сбрасывается при входе.

В старых `siwc`/`auto` `OPENAI_LANE_COOLDOWN=15m` задаёт локальную паузу повторной попытки; это **не время сброса лимита ChatGPT**. В этих режимах ошибка `subscription_sharing_user_not_eligible` отключает новые попытки до явного повторного входа. В `profiles` ошибки подписки отображаются в диагностике, не включают этот глобальный cooldown и не меняют следующий маршрут: каждый вызов использует свой профиль. Перезапуск сбрасывает локальные счётчики и паузу.

## Вход с VPS

1. Оставьте `OPENAI_AUTH_MODE=profiles` в `.env`, добавьте в TOML профиль `openai_chatgpt` с доступной моделью и направьте к нему нужную роль. Перезапустите backend. API-only пример сам по себе не включает подключение подписки. Старые глобальные `siwc`/`auto` доступны для совместимости с API-only TOML.
2. Отправьте `/chatgpt login` в личном Telegram-чате владельца; команда доступна в меню бота и возвращает ссылку и кнопку входа.
3. В браузере подтвердите вход и разрешение использовать план. Браузер перейдёт на `http://127.0.0.1:1455/auth/callback?...`; на клиентской машине страница может не открыться. Скопируйте **полный адрес** из адресной строки.
4. Отправьте `/chatgpt callback <полный адрес>` тому же боту. Срок попытки — десять минут; после рестарта начните новую попытку.
5. Проверьте каталог через `/chatgpt models`, задайте slug в `model` каждого нужного TOML-профиля и перезапустите backend. В старых `siwc`/`auto` вместо этого можно сохранить общую модель через `/chatgpt model <slug>`.

В этом VPS-потоке сервер не открывает loopback listener: адрес переносится вручную, как предлагает issue #19. Публичный callback не добавляется. Callback проверяется по точному адресу и `state`, обменивается с исходным PKCE verifier один раз; ID token проверяется по OpenAI JWKS, issuer, audience, сроку, nonce и сохранённому subject. Повторный вход использует выданный `client_id`; смена аккаунта/воркспейса в этом MVP не поддерживается. Ссылки не содержат `id_token_hint`, чтобы не передавать токен через Telegram.

Если разрешение `chatgpt.tokens.use.direct` не выдано, вход сохраняется, а оплата планом остаётся выключенной. Войдите снова с нужным разрешением или явно перенаправьте роль на API-профиль; автоматической смены оплаты в `profiles` нет. Приложение не запускает OAuth автоматически при 429/403/503. Если владелец явно повторяет вход после сохранённого входа без прямого разрешения, используется `prompt=consent`; обычный повторный вход не запрашивает согласие принудительно.

## Диагностика и хранение

`/chatgpt status` и HTTP API статус показывают режим `profiles`, активную полосу `profiles`, а для каждой роли — имя профиля, его явную модель и `auth_mode` (`api_key` или `siwc`). Состояние общего входа и разрешения плана показывается отдельно. Старый глобальный выбор модели аккаунта не описывает маршрут роли. Статус также содержит число попыток по каждой полосе с момента запуска, последний 429, локальную паузу и последний код ошибки/request ID. Проверяйте лимиты в [ChatGPT Usage](https://chatgpt.com/settings/usage).

На хосте путь задаёт `OPENAI_TOKEN_STORE` (по умолчанию `./container_data/chatgpt/credentials.json`). В Compose используется отдельный bind `container_data/chatgpt` → `/data/chatgpt`. Файл имеет права `0600`; обновление токенов атомарно, refresh сериализован, второй backend с тем же store не запускается. На Linux перед включением создайте каталог: `mkdir -p container_data/chatgpt`, затем `sudo chown 10001:10001 container_data/chatgpt` и `sudo chmod 700 container_data/chatgpt`. Токены переживают обычный рестарт и не включаются в текущий архив резервного копирования; после восстановления на другом хосте войдите заново.

Токены не возвращаются через HTTP API и не логируются. Callback-команды обрабатываются до PostgreSQL/Temporal и не попадают в разговор или prompt. В этом потоке сам callback проходит через Telegram. Не пересылайте callback другим людям. ID-token hints не используются.

HTTP-ошибки сохраняют status, code, param, request ID и ограниченное тело ответа в `siwc.APIError` в памяти. В журнал идут только status/code/param/request ID, без тела и сообщений провайдера. Терминальная ошибка refresh удаляет негодные токены, сохраняя регистрацию и host ID; сетевой сбой их не удаляет.

Запросы плана идут на `/responses` по базовому URL, по умолчанию `https://api.openai.com/v1`. В теле запроса передаются `store:false`, `stream:true`, полная история и developer-сообщения вместо system. Инструменты ядра передаются как function tools в namespace `openalbert`. Единственный успешный терминал — `response.completed`; частичные ответы и tool calls не исполняются. STT остаётся отдельным сервисом.

## Проверки

`task test:siwc` проверяет OAuth/JWKS, PKCE, scope, restart, refresh concurrency, allowlist тела Responses, SSE, fallback и owner-only команды на синтетических провайдерах. `task check` проверяет анализ Go и обе Compose-конфигурации.

Live consent и доступность preview для конкретного аккаунта проверяются отдельно реальным входом; синтетические тесты не подтверждают включение маршрута OpenAI для аккаунта.
