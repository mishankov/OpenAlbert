# Локальные проверки, сборки и релизы

[К содержанию](README.md)

Все проверки запускаются на машине разработчика через Task. Пайплайны хранятся
в репозитории: `Taskfile.yml`, `tools/local.py`, `deploy/docker-bake.hcl`.
GitHub используется для исходников, хранения образов и release-артефактов.
Отправка коммита сама по себе не запускает тесты, сборку или публикацию.

## Подготовка

Нужны Task v3, Python 3.10+, Go из `go.mod`, Node.js 24 с npm, Docker Engine
с Compose 2.23.1+ и Buildx. На macOS можно использовать уже установленный Docker
Desktop или OrbStack. Для native-проверок нужен Apple Silicon Mac с полным Xcode
и управляемая Tart VM. Установка Task на Mac: `brew install go-task`.

Один раз подготовь VM по [инструкции Tart](macos-development-vm.md):

```sh
task vm:setup
task vm:doctor
task --list
```

Браузерный сценарий сам выполняет `npm ci` и устанавливает Chromium Playwright.
На Linux системные зависимости браузера устанавливаются отдельно:
`cd docs && npm ci && npx playwright install --with-deps chromium`.
Go integration-сценарий собирает Linux-контейнер с нужной версией Go,
Chromium и FFmpeg. На хосте эти два инструмента для него не требуются.
Первый запуск скачивает зависимости и базовые образы; последующие используют
локальные Docker/BuildKit и пакетные кеши. Это локальное выполнение, не offline-режим.

## Команды

| Команда | Что выполняет |
| --- | --- |
| `task check` | gofmt без изменения файлов, go vet, тесты runner, проверка Compose и Bake |
| `task test:go` | Go race-тесты в Linux с временными PostgreSQL/VictoriaLogs, Chromium и FFmpeg |
| `task test:backup` | Зашифрованная копия, ротация S3 и восстановление PostgreSQL/MinIO в отдельных контейнерах |
| `task test:web` | Тесты/сборка docs, Playwright docs и inspector, включая клавиатуру |
| `task test:macos` | Python tooling, реальный Go/Swift-контракт, XCTest в Tart и smoke release bundle |
| `task test` | Все четыре набора тестов |
| `task images` | Семь образов для архитектуры Docker engine и smoke каждого |
| `task verify` | check, все тесты, images и чистое развёртывание с перезапуском |
| `task screenshots` | Нативные скриншоты в Tart |
| `task reports` | Сводка последнего завершившегося прогона |
| `task publish` | Полная проверка и публикация двух архитектур из чистого master |
| `task release:macos` | Проверка, стабильная подпись и локальные macOS release-артефакты |
| `task release:macos:draft` | То же с загрузкой нового GitHub draft release |

Полный прогон требует macOS. На Linux можно отдельно запускать Go, web, check и
images; `test`/`verify` завершатся ошибкой на native-этапе, а не пропустят его.
По умолчанию проверки идут последовательно, чтобы не перегружать машину.
Bake может собирать независимые образы параллельно.

В Go-наборе явно включены PostgreSQL, VictoriaLogs, реальный браузер и декодирование
аудио. S3 и SSH-контракты выполняются на этапе smoke образов. Live LLM evaluations
требуют отдельного явного запуска и не входят в проверку. Отсутствующая VM или
Docker, сбой тестов и нездоровый сервис означают ошибку всего прогона.

## Логи и отчёты

В терминале видны текущий этап, его вывод, длительность и результат. Для каждого
запуска создаётся отдельный `reports/local/<UTC-время>-<id>/`:

- `summary.md` — общая сводка и ссылки на логи;
- `result.json` — статусы, длительности, commit и теги образов;
- `NN-этап.log` — полный stdout/stderr каждого этапа;
- `go-tests.jsonl` — полные события Go-тестов; терминал показывает сводку и ошибки;
- `docs/html/index.html`, `inspector/html/index.html` — отчёты Playwright;
- `docs/junit.xml`, `inspector/junit.xml` — результаты браузерных тестов;
- `docs/results/`, `inspector/results/` — traces и скриншоты ошибок;
- `macos/<id>/` — результат VM, host-build logs и guest logs;
- `images-<arch>.json` — метаданные Bake;
- `release/` — подписанные артефакты при подготовке macOS-релиза.

Каталоги и указатель `reports/local/latest.txt` не входят в Git и Docker context.
При ошибке и отмене выполненные этапы и диагностика сохраняются. Последующие этапы
не запускаются. Остановка даёт дочерним процессам время убрать одноразовые ресурсы.
Runner использует существующую общую блокировку Tart между worktrees.

Go-сервисы работают в отдельном уникальном Compose project без опубликованных
портов, с временными данными. После теста контейнеры, тома, сеть и временный образ
удаляются. Go-пакеты выполняются с `-p 1`: они используют одну временную БД,
а тест восстановления после перезапуска меняет её глобальное состояние.
Это исключает вмешательство recovery одного пакета в активный тест другого.
Браузерные тесты выбирают свободные loopback-порты и не используют уже
запущенный сервер другого worktree. Собранные продуктовые образы остаются локально:
точные теги указаны в отчёте. Старые отчёты и их образы можно удалить вручную.

Рабочий `.env` не загружается. Проверки не наследуют Telegram/LLM, live-eval или
signing secrets; используются синтетические данные. Сборка Swift и тестовых
бинарников выполняется на хосте, запуск AppKit — только в VM. В гостя не передаются
ключи, микрофон, clipboard и личный профиль. Сбой VM не разрешает запуск на desktop.

## Публикация образов

Из чистого checkout ветки `master`, с настроенной локальной авторизацией Docker:

```sh
docker login ghcr.io
OPENALBERT_IMAGE_PREFIX=ghcr.io/mishankov/openalbert task publish
```

Команда повторяет проверки, собирает все семь компонентов через Bake отдельно
для AMD64 и ARM64, проверяет smoke и развёртывание каждой архитектуры. До завершения
обоих наборов ничего не загружается. Используются именно проверенные локальные
образы. SHA и чистота checkout проверяются снова непосредственно перед загрузкой.

После загрузки архитектурных тегов создаются общие SHA- и `master`-манифесты.
AMD64 на ARM Mac использует эмуляцию; такой выпуск может занять значительно
больше времени. Публикация всех пакетов не атомарна. При сбое повтори команду
из того же коммита; не развёртывай частично опубликованный набор.
Настройка готовой установки описана в [deployment.md](deployment.md).

Подготовка и публикация macOS-релизов описаны в [macos-updates.md](macos-updates.md).
